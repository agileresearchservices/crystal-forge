# React State Agent

---
**name:** react-state
**description:** Handle tasks involving React Context, custom hooks, state management, and tree operations. Use when modifying QueryContext, ConnectionContext, TemplateContext, ActiveClauseContext, or custom hooks like useQueryExecution.

---

## Domain Knowledge

Crystal Forge uses React Context + useReducer for state management. All state is immutable; tree mutations use helper functions that return new trees.

### Context Stack
Provider nesting order (parent to child):
1. ThemeProvider (next-themes)
2. ConnectionProvider (OpenSearch connection state)
3. QueryProvider (visual query builder state)
4. ActiveClauseProvider (selected bool clause tab)

All providers must wrap the main app; omitting a provider will cause `useContext()` to throw `Context not initialized` error.

### QueryContext
**State Shape:**
```typescript
{ query: QueryNode, pagination: { from: number, size: number }, sort?: string }
```

**Reducer Actions (15 total):**
- `SET_QUERY` - Replace entire tree
- `SET_PAGINATION` - Update from/size
- `SET_SORT` - Update sort expression
- `UPDATE_NODE` - Update single node in tree
- `ADD_NODE` - Add node to clause (auto-wraps non-bool root)
- `REMOVE_NODE` - Remove node; cleans up empty bool
- `CLEAR_QUERY` - Reset to `{ match_all: {} }`
- Plus 8 more specialized actions

**Auto-Wrap Behavior:** When adding node to non-bool root, `addNodeAtPath()` wraps entire tree in bool:
```
Before: { type: 'match', field: 'title', value: 'x' }
After:  { type: 'bool', must: [{ type: 'match', field: 'title', value: 'x' }, newNode], should: [], ... }
```

### ConnectionContext
**State Shape:**
```typescript
{
  connection: { host: string, index: string, authType: 'basic'|'apiKey'|'awsSigV4', username?, password?, apiKey? },
  isConnected: boolean,
  error?: string
}
```

**Persistence:** Saves to `crystal-forge-connection-state` localStorage; does NOT persist AWS SigV4 credentials

**Hook API:** `const { connection, setConnection, isConnected, error } = useConnectionContext();`

### TemplateContext
**State Shape:**
```typescript
{
  templates: QueryTemplate[],
  aggregationTemplates: AggregationTemplate[],
  selectedTemplate?: QueryTemplate
}
```

**Initialization:** Calls `initDB()` → `seedTemplates()` on first mount; idempotent (safe to call multiple times)

**Built-in Templates:** 18 pre-configured templates across Common, E-commerce, Advanced categories; marked with `isBuiltIn: true` to prevent deletion

### ActiveClauseContext
**State Shape:**
```typescript
{ activeClause: 'must'|'should'|'must_not'|'filter' }
```

**Usage:** Tracks which clause tab user has selected; when adding field, node goes to active clause

**Hook API:** `const { activeClause, setActiveClause } = useActiveClause();`

### NodePath Format
**Definition:** `NodePath = string[]` — describes location of any node in query tree

**Examples:**
- `[]` - Root node
- `['must', '0']` - First node in must clause
- `['should', '2', 'must', '1']` - Second node in nested bool's must clause

**Helper Functions:**
- `findNodeAtPath(tree, path)` - Returns node or null if path invalid
- `updateNodeAtPath(tree, path, newNode)` - Returns new tree with node replaced
- `addNodeAtPath(tree, path, newNode)` - Returns new tree with node appended to clause
- `removeNodeAtPath(tree, path)` - Returns new tree with node removed

### Node IDs
- **Generated by:** `generateNodeId()` → `node_<counter>_<timestamp>`
- **Unique per session:** Not persisted
- **Immutable:** Never change a node's ID during operations

### useQueryExecution Hook
**Checks:** `canExecute = isConnected && !!index && (!!query.query || aggregations.length > 0)`
- Must be connected to OpenSearch
- Must have selected an index
- Must have query OR aggregations (can't execute nothing)

**Returns:** `{ execute, loading, error, results }`

### Known Failure Modes
- **Infinite loops:** If `isEditing` flag not managed correctly in JSONPreview, visual builder changes cause JSON update which triggers visual update loop
- **Lost state:** Forgetting immutability → mutating state object directly breaks React detection
- **Type misalignment:** `query-validator` uses simplified types intentionally; don't try to align them with `query-dsl` types
- **Missing provider:** Component tries to `useContext()` outside provider → throws "Context value undefined"
- **Auto-wrap not triggering:** Non-bool root not converted to bool when adding first node to clause

## Common Tasks

### Modifying QueryContext Reducer
1. **Read:** Check current reducer switch statement in `QueryContext.tsx`
2. **Add case:** New action type + handler
3. **Immutability:** Use spread operator or helper functions (`updateNodeAtPath`, `addNodeAtPath`)
4. **Test:** Add unit test dispatching action → verify state changes correctly
5. **Integration:** Test in UI component that calls action

### Adding New Hook
1. **File:** Create in `apps/web/hooks/useMyHook.ts`
2. **Interface:** Export type definition + hook
3. **useContext calls:** Call context hooks inside your hook (not in parent)
4. **Throw if context missing:** `if (!context) throw new Error('Hook must be used within Provider')`
5. **Memoization:** Use `useMemo`/`useCallback` if returns functions/arrays

### Fixing State Mutation Bug
1. **Symptom:** State changes not reflected in UI or infinite loops
2. **Trace:** Check for direct mutations: `state.query.must.push(...)` or similar
3. **Fix:** Use spread operator or helper functions
4. **Verify:** Ensure reducer returns NEW state object, not modified original

### Adding Tree Operation Helper
1. **File:** Add to `utils/nodeHelpers.ts` or similar
2. **Signature:** `(tree: QueryNode, ...params) => QueryNode`
3. **Immutability:** Return new tree, never mutate input
4. **Path validation:** Check bounds before accessing path
5. **Test:** Test with deeply nested trees, edge cases (empty clauses, single node)

## Failure Modes

| Symptom | Cause | Fix |
|---|---|---|
| Component doesn't re-render when state changes | Mutated state directly instead of returning new state | Use spread operator or helper functions; return new state object |
| Infinite loop between visual builder and JSON | `isEditing` flag not properly managed | Set flag true before debounce, false after update |
| "Context value undefined" error | Component not wrapped in provider or hook called outside component | Move component inside provider tree; check provider order |
| Tree operation fails silently | Path doesn't exist or bounds check missing | Add console.error() for invalid paths; validate before operating |
| Auto-wrap not happening on ADD_NODE | Non-bool root not converted | Check `addNodeAtPath()` implementation; verify it detects non-bool and wraps |
| Template not loading from IndexedDB | Database not initialized or seed failed | Check `initDB()` called in useEffect; verify seed operation is idempotent |

## Do / Don't

| Do | Don't |
|---|---|
| Use spread operator for immutable updates: `{ ...state, query: newQuery }` | Mutate state: `state.query = newQuery` |
| Call helper functions from reducer (`addNodeAtPath`, `updateNodeAtPath`) | Manually traverse tree with nested loops |
| Check path exists before calling tree helpers | Trust paths are valid |
| Wrap hooks in useMemo/useCallback if returning functions/arrays | Return new array/object every render |
| Provider order: ThemeProvider > ConnectionProvider > QueryProvider > ActiveClauseProvider | Different provider order or missing providers |
| Test reducer with complex nested queries | Test only with flat queries |
| Use `throw new Error()` in hooks if context missing | Return undefined if context not found |
